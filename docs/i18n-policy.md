# 国际化与审校约定

[English](i18n-policy.en.md) · **简体中文**

界面语言由用户设置决定；项目文件语言来自 Profile `language`，不能因启动终端的 locale 而重写已有文件。现有文件保留自己的小节名，解析器同时接受中英文。用户正文、凭据、规则和来源文本不是界面文案，不能自动翻译。

## 文档配对门禁

`tests/i18n-policy.json` 登记对外文档的中英配对与尚未翻译的存量清单。登记成对的文档必须都存在，且通过相对 Markdown 链接互相指向。新增根 README/INSTALL、插件 Skill 正文与 references 文档不能悄悄落入通配例外：必须成对登记，或者以具体路径和理由登记为待翻译。清单本身也是审阅对象。

现有 nudge、inbox 和本约定必须保持中英同步。存量中文文档采取渐进翻译；清单中的 `deferred` 表示未完成，不是已翻译或已审校。修改这些文档时，优先补英文对应文档并从待办清单移入配对表。门禁只能检查文件和链接，不能证明两篇文章语义完全等价。

## 术语与译文

清单的 glossary 固定界面名 `Find files`、`Progress`、`Project guide`。测试检查各译文目录中的独立界面名，以及包含中文引号界面名的引用是否使用相同英文名称。普通叙述里大小写或上下文变化不由机械规则推断。新增术语需带原文、英文名和适用目录。

运行时 `_()`/`N_()` 包装、占位符、漏包装、语言矩阵及命令枚举继续由现有测试守住。文件模板的语言选择与双语解析另有行为测试，不以输出中“没有汉字”代替语义验证。

## 人工审校仍待完成

目前没有母语者审校记录，不能声称英文已通过人工质量审核。后续审阅者应逐份记录文档/目录、提交 SHA、审阅日期、术语、歧义与修改结果；不能在日志里记录任何令牌值。重点审查迁移、破坏性操作、预览/执行边界和恢复说明。自动检查与模型审阅不能替代这份人工记录。
