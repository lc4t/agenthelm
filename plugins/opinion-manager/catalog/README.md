# Opinion 可选模板

本目录提供可组合、可逐条选择的行为规则。模板是用户选择的偏好，不是普遍适用的行业标准；不用任何模板也是有效选择。

1. 回复风格：中文完整分析或中文简明表达。
2. 工作方法：证据核验与三层方案，或证据核验与按需分析。
3. 交付要求：完整交付与列表优先，或完整交付与简短表格。
4. 开发规范：工具职责与中文维护，或工具职责与项目语言。
5. 场景组合：完整分析与项目交付组合，或简明沟通与项目交付组合。

每个系列在一份 Profile（个人配置）中只能选择一个变体，所有规则引用精确版本。不同系列可组合；场景模板直接引用原子规则，没有模板嵌套。添加类别模板时，选择相同规则版本会去重；相反偏好占同一 slot（行为选择槽），冲突会阻断生成，不能把 scopes（适用范围说明）当作自动业务路由。

配置采用 Opinion Manager 的 catalog、profile、compose、verify 流程：先查看完整规则，预览配置与正文；用户确认后由 Agent 使用工具实际返回的指纹保存，再核验。人工修改先保留，完整读回并纳入新配置；升级必须精确选版本并保留个人修改。模板不创建 Case、不管理 Git、不自行上传或发布文件，也不实现候选计数与灰度晋升。项目路径、权限、依赖和命令由项目治理契约提供。

规则初始版本为 1.0.0；同用途的变体各自维护版本。当前推荐版本为 1.1.0：每条规则与模板提供 zh / en 双语文字，规则另带 trigger（何时适用）、purpose（为什么）、exclude（不适用于）；scopes 只是适用范围说明，不是路由。1.1.0 与 1.0.0 的行为语义一致，1.0.0 文件保持不变，模板按精确版本引用对应规则的 1.1.0。说明或拼写修订且行为不变用 patch；兼容的新增或完善用 minor；删除约束或不兼容改变用 major。版本变化都需要完整预览和确认。测试只证明相应结构及组合流程，不证明长期效果。

1.1.0 的两个场景模板（`scenario/reviewed-project`、`scenario/concise-project`）还声明了标签加载：宽集合的 10 条（简明组合 9 条）常驻规则始终读取，其余规则按 `decisions`（方案与论证）、`files`（文件与条目）、`reports`（汇报材料）、`maintenance`（规则与模板维护）四个标签按需读取，标签成员关系只写在模板里，规则文件不变。选择这些模板时，`profile` 预览会生成带标签声明的 Profile（schema 2.2），经确认后才生效；不需要分层读取时加 `--no-tags` 保持完整读取。其余模板没有声明，规则全部常驻。1.0.0 的模板与规则保持原样。
