# The Opinion migration hint in check

Since 6.14.0 opinion-manager supports on-demand tag loading and `opinion_manager.py migrate`. An existing project's opinion never changes by itself; `agenthelm check` only tells the user that there is something to migrate. The user previews and confirms with `migrate` themselves.

## When it runs, and how it is ranked

- Advisory: it does not change the exit code, is not part of `summary.up_to_date`, and `--strict` does not fail because of it.
- Only the explicit `agenthelm check` runs it. The session-start hook (`check --hook`), the nudge, `doctor` and `update` never call migrate.
- When the project has `opinion.lock.json` and opinion-manager can be found (the copy next to agent-pack first, then the newest installed one), one read-only preview runs per project, writes nothing, and times out after 5 seconds:

  `python3 <opinion-manager>/runtime/opinion_manager.py migrate --project <project> --output json`

- agent-pack and opinion-manager only call each other through a subprocess, never by import. `--offline` and `--client` make no difference (migrate does not use the network).

## Results and hints

- `status: preview` (exit code 0): one hint with the target profile and schema, a summary of the updates, the `inbox.incomplete` count, and a copyable preview command (paths are shell-quoted, so spaces and quotes still run as written). The hint carries neither `--apply` nor the confirmation fingerprint; the confirmation step comes from migrate's own preview.
- `status: cannot-migrate` with `reason` `manual-edit-conflict` or `catalog-conflict` (exit code 3): one short note and the same preview command. The wording is generated by agent-pack per reason (it follows the UI language); the manager's `message` goes into the JSON only.
- Everything else is silent: `unchanged`, `nothing-to-migrate`, `migrated`, `rolled-back`, `refused`, `failed`, any other reason, no lock, no opinion-manager installed, timeout, non-JSON output, non-object output, an unknown status, and a preview with a non-zero exit code.

## JSON

`check --output json` gains a top-level `opinion_migrate` array when a hint is shown. When silent the field is absent and existing output is byte-identical. Each item:

- `kind`: always `"opinion-migrate"`; `status`: `"preview"` or `"cannot-migrate"`; `reason`: `null` for a preview; `command`: the preview command.
- preview: `target{profile, schema_version}`, `updates[{kind, id, current, target, action}]`, `inbox_incomplete` (integer).
- cannot-migrate: `message` (the manager's own text, possibly empty).

If you do not migrate, nothing changes and current behaviour is unaffected. For the migration itself see `plugins/opinion-manager/references/versioning.md`, "Migration".
