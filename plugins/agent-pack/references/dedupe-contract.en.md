# `agenthelm dedupe` contract (schema_version 1)

中文：[dedupe-contract.md](dedupe-contract.md)

```
agenthelm dedupe --list [--output json]
agenthelm dedupe <group-id> (--keep <ref> --retire-others | --keep-all --note "..." | --ignore | --unignore)
                 [--project DIR] [--output json|text] [--lang zh|en|auto] [--apply --expect-plan <plan_digest>]
agenthelm dedupe <group-id> --keep <mcp ref> --desktop-snippet [--output json|text]
```

Groups come from the `duplicates` of `agenthelm inventory`. A group id is stable: `g-` + the first 10 hex digits of SHA-256(`kind|client|name-or-fingerprint`); it does not change when other entries appear. Preview by default, zero writes; `--apply` must carry the `--expect-plan` a preview printed and refuses on a mismatch (exit 1). Exit codes: 0 success or a preview without blockers; 1 blockers, digest mismatch or failure; 2 usage error. macOS and Linux only.

## Dispositions

- **`--keep <ref> --retire-others`** (Skill copies only): the other copies are moved to `~/.agent-pack/recovery/<timestamp>-dedupe-<group id>/skills/<name>` (the same recovery layout; several copies get a store suffix). Archiving is a move, not a delete; failures move everything back. The result gives `recovery_dir` and a one-line manual `mv`; this version has no `restore` command. A kept entry that points inside a directory to be retired -> `keep-depends-on-retired`.
- **A copy with `unknown` evidence is read-only**: if any member is `unknown` the plan is `blocked: evidence-unknown` and nothing is retired.
- **MCP copies**: only a **managed** entry (the state of this project's package records ownership: `mcps` for user level, `scopes.mcps` for local/project) is retired by the tool: `plan.retire[]` lists it (`managed: true`, a 16-hex `entry_digest`, no values); its original JSON fragment goes to `mcp/<name>@<scope>.json` in the recovery directory, the whole config file is first backed up byte for byte (`claude.json.before` / `project-mcp.json.before`, all 0600, directory 0700, never printed), `~/.claude.json` is rewritten atomically, the state drops the ownership, and any failure restores every file byte for byte; preview = apply (`plan_digest` includes the entry digest; a mismatch refuses with zero writes). Recovery stays manual: the result's `restore[]` gives the steps (put the fragment back, or restore the whole backup); there is no `restore` command. An **unmanaged** copy (hand-installed, or owned by another package name) is **never edited**: `plan.manual[]` gives the official command `claude mcp remove --scope <user|local|project> <name>` and the `cp ~/.claude.json ~/.claude.json.bak` backup reminder, each `not_archivable_by_tool: true`, `promise: cannot-promise`; non-Claude clients only get an instruction to delete the entry in that file by hand. With only unmanaged copies, `--apply` returns `manual-only` and writes nothing. A member with `unknown` evidence is still `blocked: evidence-unknown`. When another client has an entry with the same fingerprint, `warnings` has `cross-client-keep-recommended` (the same MCP across clients does not conflict; keep it, no retirement is offered).
- **`--keep-all --note`** / **`--ignore`** / **`--unignore`**: write only the machine-level decision file `~/.config/agenthelm/ext-decisions.json` (0600, atomic); its content is just `{decision, note, kind, client, key, members_digest, at}` with no values. A note is at most 200 characters and a token-like note is refused. After the group's members change, `--list` marks the decision `stale`. `--ignore` is undone with `--unignore`. None of the three changes any client configuration.

## Target judgement (#184)

The same fingerprint does not mean the same target (see "Target judgement" in the inventory contract). `dedupe` changes in three places; keys are only appended, `schema_version` stays 1, and group ids and decision-file keys are unchanged:

- `--list` no longer lists a same-fingerprint group whose targets differ or cannot be confirmed (it is in the inventory's `mcp_hints[]`). Calling `dedupe` with the old id of such a group returns `blocked: not-a-duplicate-group` with `target_relation`, `differs_in[]`, `reasons[]` and `refs[]`, no longer `group-not-found`. A `keep-all` / `ignore` recorded earlier for such a group stays in the decision file untouched, and `--unignore` gets `not-a-duplicate-group` as well; cleaning the decision file is not part of this version.
- The cross-client guard compares `target_class`: an entry of another client with the same `target_class` still raises `cross-client-keep-recommended` (`refs[]` lists only the same-target entries); an entry with the same fingerprint but another `target_class` raises nothing; when the other side or this group has an `opaque` target and the target cannot be confirmed, `cross-client-target-unconfirmed` is raised (no reason to keep). The command still offers no retirement for a cross-client set.
- A same-name group across stores (`group_kind: same-name`): when `relation` is `identical` but `target_relation` is `different` or `unknown`, `warnings` gains `fingerprint-collision` (the fingerprints match but these may not be the same service; confirm the targets before acting).

## Paste-ready Desktop snippet (read-only)

`--desktop-snippet` prints the path of `claude_desktop_config.json` (macOS `~/Library/Application Support/Claude/`, Linux `~/.config/Claude/`), a JSON fragment to merge into `mcpServers` (structure `command`/`args`/`url` only; environment variables are listed by name with a `<fill in your NAME>` placeholder) and the hint to fully quit and restart Desktop. An entry with an inline credential is `blocked: inline-secret` and yields no snippet. Whether Desktop loads remote `url` entries, headers or SSE is not documented; the snippet carries `notes` marked unconfirmed, and `promise` is always `cannot-promise`. The Desktop config file is neither read nor written.

## Impact (`plan.impact`, `--keep … --retire-others` only)

The preview gains the plan key `impact`: first it works out what each client can still read after this retirement, then it writes the result as warnings (design and trade-offs: `docs/design/inventory-recommendations.md` section 3). `--keep-all`, `--ignore` and `--unignore` change no configuration and carry no `impact`.

- **`schema`** (1), `kind` (`skill|mcp`), `name`, `basis` (always `file`: computed from the file locations each client reads; whether a copy is really loaded depends on client settings, which this command does not read).
- **`clients{<client id>: …}`**: one row per client, from the locations its driver declares (`stores`, `undetermined` ones excluded): `detected`, `reads[]`, `before[]` / `after[]` (entry references), `after_stores[]` (where a copy can still be read after the change), `verdict`, `evidence` (`file|unknown`), `reasons[]`, and `via_before[{ref,path,chain[],resolved}]` when a symlink is taken down with the archived directory. Clients of the default set are always listed; other registered clients only when detected on this machine; a client with no copy before and none after is not listed.
- **`verdict`**: `unchanged` (the set of content digests the client can read is the same before and after) | `lost` (it had a copy, now it has none) | `replaced` (it still has an entry of that name, with a different digest set) | `gained` (it had none, now it has one) | `uncertain` | `unknown`. Reasons for `uncertain`: `compat-copy-present` (a copy of that name sits in a location the driver lists under `compat_reads`; it only affects `lost`), `project-approval-unknown` (the remaining copies are only in a store that declares `approval_required`, such as Claude's project-level `.mcp.json`), `project-trust-unknown` (only in a store that declares `trust_required`). Reasons for `unknown`: `evidence-unknown`, `store-undetermined`, `link-chain-too-deep` (more than 8 hops, or a loop). Reasons for `lost`: `link-target-retired`, `entry-retired`, `no-other-copy`. With insufficient evidence only the reason code is given: never `lost` and never "not affected".
- **`lost_clients[]` / `uncertain_clients[]` / `unknown_clients[]`**, **`dangling_after[]`** (paths of symlinks that will dangle) and **`scope_notes[]`**: `affects-all-projects` (a user-level entry is retired, so every project of that client is affected; the list of projects on this machine is not provided), `other-machines-lose-it` (`relocate` only: a project-level entry moves to user level; the tool does not check whether it is committed).
- **Skill path semantics**: an archived entry is identified by `realpath(parent directory)/name`. When a real directory is archived, every symlink that resolves into it dangles; when a symlink itself is archived, only that link disappears.
- **MCP**: entries have no chain; the archived set is (store, name). A same-fingerprint group with different names is judged over all member names.
- **New `warnings` codes** (`message` follows the interface language and is not part of `plan_digest`): `impact-lost-client` (one per `lost` client, with `client` and `ref`), `impact-uncertain` (one per `uncertain` or `unknown` client, with `client` and `reasons`), `impact-dangling-link` (with `paths`), `impact-other-machines`. **`status` is not changed by the impact** (warnings only: no new blocker and no new confirmation flag); the text preview renders them as one "Impact: …" group instead of printing each as a "Note:" line.
- `impact` is part of `plan_digest`: if the files change after the preview so that the impact changes, `--apply` refuses on the digest mismatch and writes nothing. `impact` holds references, paths (abbreviated with `~` and `<project>`), content digests and codes only: no file content, env values or tokens. Keys are only appended; `schema_version` stays 1.

## JSON

`{schema_version, command: "dedupe", mode: "list"|"preview"|"apply"|"desktop-snippet", ...}`. `plan` keys: `group`, `kind`, `disposition`, `status` (`ready|blocked|manual-only`), `members[]`, `steps[{id,action,promise}]`, `blocked[{code,message}]`, `warnings[{code,message}]`, `manual[]`, `retire[]`, `plan_digest`, `next.apply`. `plan_digest` does not depend on the interface language. Keys are only appended; output contains no env values, header values or tokens.
