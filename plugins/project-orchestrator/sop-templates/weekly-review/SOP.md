# {{title}}

## 目的

回看本周所选事项实际完成了什么、卡在哪里，沉淀经验，并定下下周最重要的几件事。

## 前置条件

- 命令：agenthelm｜用途：读取所选事项的进展（`agenthelm project progress --output json`）｜安装：见 agenthelm 的 INSTALL.md｜缺失时：询问用户

## 步骤

1. 确定复盘范围
   - 输入：要纳入的事项（标签、事项名或编号）
   - 检查点：范围由用户明确给出，不默认纳入全部事项
   - 需确认：是
   - 说明：复盘会读取所选事项的工作记录，其中可能有个人进度。未被用户纳入的事项一律不读、不写进复盘；复盘文档只留在运行它的这个项目里，该项目若会公开，不要用本流程复盘个人进度
2. 收集所选事项的进展
   - 工具：agenthelm
   - 输入：本周的起止日期；上一步确定的范围
   - 中间产物：进展清单（事项、状态、本周的工作记录）
   - 检查点：只覆盖范围内的事项，且覆盖其中所有进行中和本周关闭的
3. 对照上周计划
   - 输入：上一次复盘文档里的“下周计划”
   - 检查点：每条计划都有结论：完成 / 未完成及原因
4. 写复盘文档
   - 输入：以上步骤的结果
   - 最终产物：本 Case 目录内的 docs/review-日期.md（使用本目录 templates/review.md 的结构）
   - 检查点：所有小节都有内容，结论有依据（指向事项或文件）；开头写明本次范围
5. 规划下周
   - 输入：复盘文档里的未完成项与阻塞
   - 检查点：不超过用户设定的数量；每项有明确的下一动作
   - 需确认：是
   - 说明：下周计划由用户决定，只提出建议
6. 登记交付物
   - 说明：把复盘文档登记为 Case 的交付物

## 完成标准

- 复盘文档已保存在本 Case 目录内，开头写明了范围，并登记为交付物
- 下周计划已经用户确认

## 例外与回退

- 所选事项本周没有任何记录：照实写“本周无记录”，并提示用户是否漏记
- 用户后来想把复盘公开或分享：先由用户逐段确认哪些内容可以公开，再复制出去，不直接移动原文档
