# {{title}}

## 目的

【待补充】这个流程要达成什么结果，一两句话。

## 前置条件

每行一项：`- 种类：名称｜用途：…｜安装：…｜替代：另一项的名称｜缺失时：询问用户`。
种类可用：命令、模块（Python 模块）、环境变量、路径、技能、MCP、手动确认。缺失时可用：询问用户、停止、跳过该步、使用替代。
API 密钥只写环境变量名，不写密钥本身。确实不需要任何工具时写“无”。

- 命令：【待补充】｜用途：【待补充】｜安装：【待补充】｜缺失时：询问用户

## 步骤

每步一个编号，下面用缩进的子项补充；可用子项：工具、输入、中间产物、最终产物、检查点、失败时、需确认、说明。
“工具”里写的名称必须在上面的前置条件里声明过。

1. 【待补充】第一步做什么
   - 工具：【待补充】
   - 输入：【待补充】
   - 中间产物：【待补充】
   - 检查点：【待补充】怎样算这一步做对了
   - 失败时：【待补充】（不写则按“执行约定”处理）

## 完成标准

- 【待补充】怎样才算整个流程做完了（能被检查的条件，例如“成品文件存在于 …”）

## 例外与回退

- 【待补充】常见的例外情况和处理办法；没有就写“无”。
